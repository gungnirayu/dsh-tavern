# 人物卡加 MVU

目标：前台写剧情，后台按规则更新变量，状态栏读取变量显示。格式约定见 [MVU 卡格式约定](references/mvu-format.md)，先读它。

## 做法

1. 读卡：`tavern_read_card` 看设定、各开场和世界书，找出随剧情变化的状态（时间、地点、关系、物品、线索等）。固定设定留在原文，不必搬进变量。
2. 决定改哪张卡：新建的卡直接在原卡上改；用户要保留原卡时先 `tavern_copy_card` 建副本，再改副本。
3. 写变量：每个开场末尾加 `<initvar>` 与 `<mvu-status/>`，各开场字段一致、值按场景填。
4. 写规则：世界书加 `[mvu_update]` 条目，讲清每个字段的变化依据；可选加 `[initvar]` 条目。
5. 写面板：按题材设计 HTML，可以用样式和脚本自由发挥；原卡已有状态栏美化时，优先改造它的 HTML 来读 MVU 变量，保留原来的观感。
6. 清理旧协议：原卡里要求模型在正文输出状态块的说明、示例和对应正则，删掉或改写；与状态无关的美化、脚本、正则保留。
7. 校验：保存工具结果已附带校验，直接改文件时调用 `tavern_validate_card`；修正全部 errors，再看 warnings 是否需要处理。

改哪里、怎么改由你判断，按改代码的方式一次改完再校验，不必拘泥步骤顺序。校验只覆盖静态格式，不代表真实游玩已经验证；用户要求时才做真实试玩。
