# Tavern 自动压缩方案（已确认并实现）

## 用户行为

在 Tavern 设置增加「上下文压缩」：默认「手动」，可选择「每 N 轮」或「上下文达到 X%」。两种自动模式互斥，手动压缩按钮始终保留。配置属于 Tavern 全局设置，进度按游戏分别保存；修改后在下一个安全边界生效。

- 每 N 轮：按已完成的有效剧情轮计数，不计工具调用、候选生成、生图和后台任务；重写同一轮不重复计数。启用或修改轮数模式从当前进度重新计数。成功的手动或自动联合压缩重置计数。
- 百分比：使用前台当前模型的上下文容量和宿主原生 token 计量。取请求上下文占用，不取累计消耗或费用统计；标明为估算值。模型容量未知时明确提示该模式无法判断，不猜测容量。
- 达到阈值后由服务端执行。优先在本轮正文和后台结算完成后、下一轮模型请求前压缩；后台正在执行时等待安全边界，不取消结算。玩家已提交的下一条消息须保留，联合压缩结束后再继续，不要求玩家重发。
- 自动处理仅显示简短状态，不弹出确认框、不插入剧情正文。失败时给出可操作的提示，不能高频重复请求压缩；下一轮是否继续须结合容量检查，不能把失败当成功。

## 前后台共同处理

复用现有 Tavern 压缩协调器与原生压缩接口，把「准备 → 前台压缩 → 后台压缩 → 结果落盘」收归服务端；手动按钮调用同一个入口。前台沿用剧情压缩提示词，后台沿用其原有提示词。没有后台 Session 时正常跳过，不为了压缩创建后台。

这里的后台指 Timeline 绑定的剧情后台 Agent；生图、卡片编辑等独立任务不随前台一起压缩。联合压缩时阻止新的冲突任务进入。前台成功、后台失败时记录部分成功，后续只补失败侧，避免反复压缩已成功的一侧。重启恢复时依据原生压缩事件和持久操作记录核实结果，不盲目重发。

继续使用原生 Session 压缩，保留 append-only 事件历史、人物卡和固定世界书系统背景。维持后台压缩后回退需要重建 Session 的现有约定。回退与分叉根据有效 Timeline 恢复进度，不以消息数组总长度或旧分支累计轮数触发。

## 实现边界

- 手动入口位于 `tavern-plugin/src/client/main.js` 的 TavernCompactionAction，现统一调用服务端 `runCompaction`。
- `auto-compaction.js` 将操作、各侧结果和计数基线持久化到 Chat。
- 当前检查的 DSH compaction-basic 实现默认 auto=true、thresholdRatio=0.8，同时包含窗口溢出恢复。必须明确接管 Tavern 会话的自动策略，保证默认手动；不得修改宿主全局行为或影响其他 Profile。不能通过界面开关掩盖仍在运行的宿主自动压缩。
- 自动压缩和后台结算必须共享任务准入边界，避免检查空闲后又插入新任务的竞态；不依赖页面轮询触发。

## 验收

验证默认手动、N 轮、百分比、模型切换和未知容量；验证手动重置、重写不重复计数、回退与分叉。用真实 DSH Session 加模拟模型验证前后台串行、用户消息等待后继续、部分失败不重复成功侧、页面关闭和服务重启恢复。检查实际 provider 请求确认压缩生效、固定背景仍在；原始事件不可被删除。
